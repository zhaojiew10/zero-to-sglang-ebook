# 阅读与实践指南

## 先修知识与阅读方式

本书适合具备 Python 和基础深度学习知识的读者。第一部分主要建立概念，不要求先有 CUDA 经验；第二部分可以在原课程提供的 mini-sglang 代码基础上逐步实践；第三、四部分建议结合真实 SGLang 源码和官方文档阅读。

推荐路径：

1. 先读第 1—5 章，统一 Prefill、Decode、KV Cache、Roofline 和 Benchmark 的语言。
2. 再按第 6—15 章的顺序构建引擎，不跳过请求状态和正确性验证。
3. 根据工作负载选择第 16—20 章的进阶主题，不把所有优化都当作必选项。
4. 最后通过部署、Trace 和 PR 流程形成“问题—证据—修改—验证—协作”的闭环。

## Part 0：开始之前

原课程的 Part 0 包含两项准备：

- **编码伦理与开源精神**：拥有并理解自己的代码，像开发者一样沟通，先 profile 再优化，遵守项目许可与协作规范。
- **部署第一个 SGLang 服务**：准备环境并运行小模型，确认后续学习有可用基线。

本书将编码伦理融入第 22—23 章，将部署实践集中在第 21 章。若希望严格按原课程学习，可先阅读[原项目 Part 0](https://github.com/datawhalechina/zero-to-sglang/tree/main/course-material/ch/part0)。

## 环境与版本

原课程、mini-sglang 和 SGLang 都会持续演进。本书的参考 commit 见[资料来源、许可与版本](sources.md)。执行书中的实践命令前，应核对当前官方安装文档、操作系统、Python、PyTorch、CUDA、GPU 和模型版本。

## 实践原则

每个实验至少回答：**结果是否正确、性能是否改善、证据能否复现**。

- 保留原始版本和独立参考实现，先验证输出再计时。
- 固定模型、dtype、提示词、输入与输出长度、并发、采样参数和硬件环境。
- 区分 TTFT、TPOT、ITL、端到端时延、吞吐和 Goodput，报告中位数与尾延迟而非只报最快一次。
- 性能症状需要通过 Profiling 或 Trace 验证机制，不从代码外观直接推断瓶颈。
- 优化通常有适用边界：量化影响精度，缓存增加管理成本，并行引入通信，PD 分离增加 KV 传输。
- 不把原课程或原 PR 的数据写成本机实测；复现失败时保留完整环境与错误栈。

## 代码与命令

本书将原课程的概念说明和代码走读合并。完整可运行代码以 [mini-sglang](https://github.com/sgl-project/mini-sglang) 和 [SGLang](https://github.com/sgl-project/sglang) 为准，标为“伪代码”的片段只用于解释机制。

整合书中片段时，应补齐配置、异常处理、资源生命周期、请求取消、并发安全和测试。涉及部署、分布式、量化或后端选择的命令，必须根据当前官方文档确认参数仍然有效。

## 阅读检查清单

- 本章优化针对计算、访存、显存、调度还是通信瓶颈？
- 请求状态、KV 数据和张量形状在改动前后如何变化？
- 正确性由什么独立结果或测试保证？
- 性能数字的测量区间、负载和硬件是什么？
- 新机制的额外内存、传输、精度或工程复杂度是否值得？
